# StudyFlow: статический лендинг

Второй этап итогового проекта. Одностраничный адаптивный сайт на чистых HTML, CSS и JavaScript, без React и сборщика.

На странице: описание проблемы и идеи, возможности, интерактивный пример планировщика, три шага использования, вопросы и заметные переходы к демо. Текст отделяет концепцию продукта от демонстрационного интерфейса.

## Локальный запуск

Из этого каталога:

```sh
node serve.mjs
```

Открыть `http://127.0.0.1:4173`. Установка npm-пакетов не требуется. Альтернатива: открыть `dist/index.html` напрямую в браузере. Для полной проверки поведения ресурсов рекомендуется HTTP-сервер.

## Файлы

```text
dist/
  index.html                  # Семантическая разметка и содержимое
  styles.css                  # Адаптивность и визуальное оформление
  script.js                   # Меню и демонстрационные взаимодействия
  assets/
    favicon.svg               # Знак StudyFlow
    manrope-variable.ttf      # Локальный шрифт
    OFL-Manrope.txt            # Лицензия шрифта
serve.mjs                     # Локальный статический HTTP-сервер
.github/workflows/pages.yml    # Автоматическая публикация на GitHub Pages
```

Весь `dist/` готов к размещению на статическом хостинге. Сборка не требуется. Шрифт Manrope хранится локально, страница не отправляет запросы на внешние CDN. Источник: [Google Fonts, Manrope](https://github.com/google/fonts/tree/main/ofl/manrope), лицензия SIL OFL 1.1 приложена.

## Взаимодействия

- Мобильное меню с `aria-expanded`, закрытием по Escape и при выборе ссылки.
- Переходы к разделам и интерактивному примеру.
- Фильтры демонстрационных задач по предмету и периоду.
- Отметка выполнения обновляет счётчик и progress bar.
- Кнопка сброса возвращает пример в исходное состояние.
- Вопросы открываются нативным элементом `details`.

Демо работает в памяти страницы, не использует сервер, авторизацию или `localStorage`. Данные и даты в нём иллюстративные. После перезагрузки изменения сбрасываются.

## Доступность

Разметка содержит `header`, `nav`, `main`, `section`, `article`, `footer`, последовательную иерархию заголовков и ссылку пропуска навигации. У интерактивных элементов есть подписи и видимый фокус, фильтры объявляют состояние, изменения демо озвучивает `aria-live`. Информация не передаётся только цветом. Учитывается `prefers-reduced-motion`. Основной контент и FAQ доступны без JavaScript, меню остаётся видимым.

## Публикация

Адрес лендинга: [StudyFlow на GitHub Pages](https://1nnokent.github.io/studyflow-landing/).

Репозиторий исходников: [1nnokent/studyflow-landing](https://github.com/1nnokent/studyflow-landing).

Файлы сайта находятся в `dist/`, настройки публикации — в `.github/workflows/pages.yml`.

GitHub Actions публикует только содержимое `dist/`, без сервера и сборки. Workflow запускается при изменении сайта в ветке `main` либо вручную на вкладке **Actions → Publish StudyFlow to GitHub Pages → Run workflow**. В **Settings → Pages → Build and deployment** выбран источник **GitHub Actions**.

Чтобы обновить сайт после редактирования:

```sh
git add dist
git commit -m "Update landing"
git push origin main
```

Дождаться зелёного статуса публикации на вкладке Actions. Все пути ресурсов относительные, поэтому сайт работает в подкаталоге `/studyflow-landing/`.

## Проверка второго этапа

Проверено в Chromium на базе установленного Chrome:

- Ширины 320, 360, 390, 560, 768, 1024 и 1440 px: горизонтальная прокрутка отсутствует.
- Фильтры периода и предмета, пустой результат, отметка выполнения и обновление прогресса.
- Возврат исходных данных кнопкой «Сбросить».
- Выбор предмета на телефоне, открытие меню, закрытие по Escape и переходу к разделу.
- Открытие FAQ, корректные цели якорных ссылок, доступность основного содержимого и навигации без JavaScript.
- Ошибок выполнения JavaScript и загрузки ресурсов в браузере не обнаружено.

Лендинг соответствует объёму этапа 2: презентация продукта, адаптивный интерфейс, примеры экранов и заметный призыв посмотреть демо. Реальный CRUD, учётные записи, API и постоянное хранение относятся к последующим этапам.
