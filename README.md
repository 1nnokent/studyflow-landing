# StudyFlow

Персональный планировщик учебных задач. Предметы, сроки, приоритеты и прогресс в одном приложении.

- [Открыть приложение](https://1nnokent.github.io/studyflow-landing/app/)
- [Лендинг проекта](https://1nnokent.github.io/studyflow-landing/)
- [Репозиторий](https://github.com/1nnokent/studyflow-landing)

## Возможности MVP

- Обзор ближайших сроков, сегодняшних и просроченных задач, прогресс по предметам.
- Создание, просмотр, редактирование, выполнение и удаление задач.
- Управление предметами: создание, переименование, выбор цвета, удаление пустого предмета.
- Поиск, совместные фильтры по предмету, статусу, приоритету и сроку, сортировка и пагинация.
- Валидация форм и сообщения об ошибках с сохранением введённого текста.
- Сохранение данных после перезагрузки, экспорт и восстановление резервной копии.
- Состояния загрузки, ошибки, пустого списка, пустого поиска и отсутствующей страницы.
- Адаптивная вёрстка и управление с клавиатуры.

При первом открытии загружается пример учебной недели. Его можно изменять либо очистить на странице «О приложении» и начать собственный план.

## Требования и запуск

Нужен **Node.js 24.15 или новее**. Версию можно проверить командой `node --version`.

Из корня репозитория:

```sh
npm ci
npm run dev
```

Приложение: `http://127.0.0.1:5173/studyflow-landing/app/`.

Лендинг второго этапа находится в `dist/index.html`. Для отдельного локального просмотра лендинга сохранён `node serve.mjs`, адрес `http://127.0.0.1:4173`.

## Сборка и проверка

```sh
npm run typecheck
npm test
npm run test:e2e
npm run format:check
npm run build
npm run preview
```

`npm test` запускает unit- и компонентные тесты на Vitest и React Testing Library. Проверяются редьюсеры, асинхронные состояния, фильтры, даты, валидация, импорт, сохранение данных и работа форм.

`npm run test:e2e` запускает Playwright в установленном Google Chrome. В трёх сценариях проверяются полный CRUD-путь, перезагрузка, резервная копия, ошибки, мобильное меню и адаптивность всех основных страниц. Сервер разработки запускается автоматически, если ещё не работает. Для Chromium вместо Chrome: выполнить `npx playwright install chromium`, затем задать переменную окружения `PLAYWRIGHT_CHANNEL=chromium` перед запуском тестов.

`npm run format` форматирует исходники через Prettier.

Сборка создаёт каталог `build/`: лендинг в корне, React-приложение в `build/app/`. Предварительный просмотр приложения: `http://127.0.0.1:4173/studyflow-landing/app/`.

## Структура

```text
frontend/
  src/
    app/           # Store, типизированные хуки и маршруты
    api/           # Асинхронный адаптер localStorage
    components/    # Кнопки, поля, диалоги, строки задач, оболочка
    data/          # Пример учебного плана
    domain/        # Типы, даты, фильтры, валидация и импорт
    pages/         # Обзор, задачи, карточка, форма, предметы, данные
    state/         # Слайсы tasks, subjects, ui и createAsyncThunk
    styles/        # Стили и адаптивность
    test/          # Компонентные тесты и настройка окружения
  e2e/             # Сквозные браузерные сценарии
  public/          # Favicon и лицензия шрифта
dist/              # HTML/CSS/JS лендинга второго этапа
scripts/           # Подготовка общей публикации
.github/workflows/ # Проверки, сборка и публикация
```

## Архитектура и данные

Стек: React, TypeScript, Redux Toolkit, React Router, Vite. TypeScript работает в строгом режиме, глобальное состояние разделено на слайсы задач, предметов и уведомлений.

Компонент отправляет `createAsyncThunk`, thunk вызывает адаптер данных, редьюсер обрабатывает `pending`, `fulfilled` и `rejected`. Изменения попадают в store после успешного сохранения. При ошибке данные интерфейса не подменяются несохранённой версией.

Текущий адаптер хранит план в `localStorage` под ключом `studyflow.workspace.v1`. Асинхронная задержка позволяет проверить состояние загрузки. На следующем этапе методы адаптера можно заменить HTTP-запросами, сохранив типы операций и интерфейс компонентов.

Основные сущности MVP:

- `Subject`: идентификатор, название, цвет, дата создания.
- `Task`: идентификатор, предмет, название, описание, календарный срок либо `null`, статус, приоритет и временные метки.

Один предмет содержит несколько задач. Предмет с задачами нельзя удалить, пока они не перенесены или не удалены. Статусы: `todo`, `in_progress`, `done`. Приоритеты: `low`, `medium`, `high`. Просрочка вычисляется по календарной дате устройства и не хранится как отдельный статус.

Формат резервной копии имеет `schemaVersion: 1`. Импорт проверяет поля, даты, идентификаторы, повторения и связи между задачами и предметами. Некорректный файл не заменяет существующий план. Замена и очистка требуют подтверждения в интерфейсе.

## Маршруты

| Страница              | Путь внутри приложения |
| --------------------- | ---------------------- |
| Обзор                 | `#/` и `#/dashboard`   |
| Список задач          | `#/tasks`              |
| Новая задача          | `#/tasks/new`          |
| Карточка задачи       | `#/tasks/:id`          |
| Редактирование        | `#/tasks/:id/edit`     |
| Предметы              | `#/subjects`           |
| О приложении и данные | `#/about`              |

HashRouter позволяет открывать и обновлять вложенные страницы на GitHub Pages без серверной настройки маршрутов. Поиск, фильтры и номер страницы списка хранятся в URL.

## Публикация

GitHub Actions запускает `npm ci`, unit- и компонентные тесты, проверку типов и production-сборку. После успешных проверок публикуется весь `build/`, поэтому лендинг и MVP доступны по разным ссылкам.

```sh
git add .
git commit -m "Update StudyFlow"
git push origin main
```

Статус: **Actions → Publish StudyFlow to GitHub Pages**. Ручной запуск доступен через **Run workflow**. Источник в **Settings → Pages**: **GitHub Actions**.

## Ограничения третьего этапа

Данные хранятся только в текущем браузере и не синхронизируются между устройствами. Перед очисткой браузера нужно скачать резервную копию. В MVP нет настоящей регистрации и серверной авторизации. Собственный backend, постоянная база данных и интеграция с ними относятся к четвёртому этапу.

Шрифт [Manrope](https://github.com/google/fonts/tree/main/ofl/manrope) хранится локально и распространяется по SIL OFL 1.1. Лицензия приложена к лендингу и приложению.
